## 已采用的资源优化

以下四张图片保持原尺寸，RGBA 全部字节及透明度逐一校验一致；没有缩小纹理分辨率。

图片像素尺寸保持不变，因此解码后的像素缓冲及 GPU 纹理显存不因换编码而减少；本项收益是下载和磁盘体积。

目录整理和首轮四张图片压缩后，部署资源总量约从 24.60 MB 降至 21.85 MB。随后启用云图 v2–v8，发布包包含八张图集，总量约 31.27 MB；默认仅请求 v1（1.48 MB）；首次选择全部云形的少、中、多档时补充七张（合计 9.39 MB），后续切换复用同一份素材。八张解码像素合计约50.4 MB，比默认单张约6.3 MB增加约44.1 MB；这属于用户开启全部云形后的固定开销，不随切换次数增长。构建文件总量不等同首次页面流量；音乐仍在用户开启后请求。

MP3 已使用约55–90 kbps、32 kHz双声道编码，本轮没有继续降低码率。字体合计约113 KB，未为有限收益改动字形。银河原图等制作资源没有进入构建，Ogg 保留为音乐生成源；这些不计入网页传输收益。

云图 v2–v8 已以 v1 为视觉参照，通过内置 ImageGen 直接重制白亮云顶与冷蓝内部阴影。重制后的生成 PNG 无损转码合计 12,484,148 B → 9,388,320 B，减少 3.10 MB（24.80%）；仅编码这一步与生成 PNG 逐像素一致。八张均为 1774 × 887，v1 不变；未叠加额外运行时色彩校准。

可复现编码工具：`scripts/assets/optimize-texture.py`。本次原图、候选和像素校验报告放在 `tmp/asset-optimization/`，构建前后统计放在 `tmp/reports/resource-optimization.json`。

## 手机绘制优化（2026-10-18）

冬季原先在片元阶段隐藏88%的阔叶，但仍提交全部顶点。现在初始化时按完整叶片的冬态排名排序索引，近远景分别用二分查询调整绘制范围；原着色器继续裁定浮点边界，树量、可见叶片、顶点属性、矩阵及阴影保持一致。每型树冠320片叶在严冬只需提交39片，近景每树每次绘制1,920→234三角形，远景640→78；回暖恢复全部叶片，逐帧不重建或上传索引。

雪花四宫格离线从1024²缩至512²，保留RGBA、mipmap和原图。每格仍有256²像素，实际雪花最大34屏幕像素；资源275,270→160,348 B，含mipmap的RGBA纹理预算约5.33→1.33 MiB，解码像素少3 MiB。旋转三角函数从逐片元移至逐粒子顶点，整点不可见时先跳过采样；旋转UV边缘仍统一采样后处理透明度，保持隐式mipmap导数有效。雪花数量、尺寸、运动及三层共享贴图机制不变。复现脚本为 `scripts/assets/bake-snowflake-atlas.mjs --check`，来源和透明度覆盖记录见 `prompts/textures/snowflake-atlas-runtime-v1.json`。

## 已处理的长期运行问题

### 鲸豚事件历史

原时间线保留所有历史事件，且生成海豚事件时扫描历史鲸鱼。现为鲸鱼、海豚各16条滚动缓存，绝对周期计数独立维护；相同种子和过去时间查询仍可重现，历史查询不会替换正在播放的缓存。

同一种子跳到三天模拟时间的 Node 测量：

- 原缓存19,190条，现32条，缓存条数减少99.83%。
- 三次跳转中位耗时约396毫秒降至55毫秒；这属于大跨度时间查询，不能据此推算帧率提升。
- 超大跳时及缓存外的历史查询仍需要按时间生成，CPU耗时随目标时间增长；常规连续运行的保留内存有界。

对应行为回归覆盖原结果指纹、长时与16倍速、回拨重现、鲸豚避让。独立 Node 时间线进程在1、16、96小时模拟时间后强制GC，JS堆约3.82、3.85、3.86 MiB，缓存始终32条；这不代表完整浏览器场景内存。

### 路灯重复计算

白天和全部关灯时跳过选灯；静止夜景复用选择，镜头位置或画质变化时才重新选择。使用固定大小缓冲代替每帧创建距离对象并对全部路灯排序，保持原亮度、数量和最近灯选择。

这个优化消除了不必要的分配，原开销只有微秒级，不是主要 CPU 瓶颈。

## 镜头外绘制优化（2026-10-18）

`scene-visibility.js` 为普通网格补齐原生视锥剔除，动态实例只在矩阵、数量或几何变化时重算包围球；天空、粒子和未知顶点位移保留各自处理。主相机和阴影相机独立裁剪，镜头外仍能投到画面中的阴影不会直接消失。蝴蝶、蜜蜂、蜻蜓、林鸟、松鼠及夏夜昆虫离开镜头后跳过姿态上传，行为时钟继续，转回时立即刷新。

森林的原九批实例横跨全岛，原生剔除无法省去同批内的镜头外树木。`forest-visibility.js` 保留原矩阵、索引、画质计数和栖息地查询，另按40米网格建立140个空间块；分块共享静态顶点，实例根属性与颜色按原索引映射，风雪编译器、LOD、冬季 drawRange 和阴影深度材质保持同步。主视野保留森林三角形比例低于50%时启用分块，达到60%时恢复原九批次，避免临界视角反复切换；全景回退时同时隐藏空间块网格，减少无收益的遍历。

本机 Chrome/ANGLE Metal（Apple M4）使用真实 `createIsland`、固定时间和镜头、960×640画布、1倍像素比例及2048阴影贴图做 A/B。每轮预热25帧，采用 A/B/B/A 顺序采样各100帧，通过 `EXT_disjoint_timer_query_webgl2` 测量 GPU 时间，绘制次数和三角形包含主画面与阴影。全景保持原绘制量；朝向海面、森林大部分在镜头外时才减少大量提交。此测试用于核对森林绘制收益，未包含主页面海面、大气、后期处理和帧率上限，不能直接换算整站或手机 FPS。原始记录保存在 `tmp/reports/forest-visibility/browser.json`，主场景另做桌面和触屏手机视觉验收。

最终目标视角三角形从7,861,872降至5,433,874（减少30.9%）；两次 GPU 中位数的平均从11.05降至9.57毫秒（降低13.4%）。保留镜头外投影使总绘制次数从74增加至223，CPU 提交中位约1.0–1.1升至1.7–1.9毫秒，因此只在收益明显时启用分块。全岛仍为172次绘制/4,876,953三角，森林近景仍为81次/7,855,280三角。剔除辅助器自身 Node 微基准中位0.022毫秒、P95 0.051毫秒，不等同于整帧耗时。全岛与近景画面对比逐像素一致，目标视角仅有极少阴影栅格差异，未出现应用或 WebGL 错误。

洞前花头采用三圈独立错落实例化叠瓣，单花560个三角形，连同茎叶每簇两批、六簇最多12次可见绘制（原整片2次）。圆润花头较原六瓣增加几何成本，测试限制单花不超过560个三角形；花瓣纹理约245KB，新增共享花粉颗粒纹理约380KB；单瓣UV驱动根部至边缘的颜色渐变，不增加绘制批次。两张纹理在首帧后与既有细节资源一起加载。松鼠毛皮增强仅调整原材质，不增加模型面数、绘制批次或贴图采样次数。
